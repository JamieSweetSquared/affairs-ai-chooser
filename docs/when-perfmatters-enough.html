Decision question

Is the bottleneck front-end bloat on WordPress you already own (too many scripts, unused CSS, missing lazy-load, optimizer sprawl), or is it hosting / TTFB, a theme you should replace, or a stack problem that is not speed at all?

Who the Perfmatters path fits

A WP + Perfmatters path is a strong research candidate when most of these are true:

  • The site of record is already WordPress and you want performance controls on that site — not a migrate-off-WP project.
  • Hosting is “good enough” (or you already upgraded once) and the next pain is what the page loads, not raw server response alone.
  • You want a lightweight script manager / delay / lazy-load style toolkit rather than stacking three overlapping “all-in-one speed” plugins.
  • You will measure yourself (PageSpeed Insights, CrUX, Search Console) — Affairs does not publish invented before/after scores.
  • You are not shopping for email, funnels, memberships, or CRM on this page — those are separate niches on this site.

When faster hosting (or fewer plugins) comes first

A performance plugin is usually the wrong first buy when the evidence points elsewhere. Related (internal, non-CTA): methodology · SEO / visibility for solos · guides hub · chooser.

  • Server response / TTFB is clearly poor — fix hosting or caching at the host layer before adding another optimizer.
  • You already run multiple conflicting speed plugins — adding Perfmatters on top without removing overlap can make things worse.
  • You do not run WordPress (static, hosted builders, etc.) — this product path does not apply.
  • The real job is content / offer / list — speed tooling will not invent demand (see the chooser for tool-fit by need).
  • You expected Affairs to publish lab scores proving “X ms faster” — we will not invent those.
